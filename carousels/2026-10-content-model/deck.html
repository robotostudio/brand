01The pattern

Designers build pages. Editors publish things: products, people, case studies.

02The tell

Fields named after the layout.

// schemas/homepage.ts
defineType({
  name: 'homepage',
  fields: [
    heroTitle,
    heroTitleLine2,
    section3Text,
    section3TextAlt,
  ],
})
03Six months later
  1. Week 1Marketing wants a new page
  2. Week 2No field fits, so they paste HTML
  3. Week 6The same case study lives in four places
  4. Month 6"We need a new CMS."
04The fix
Page model

One homepage document with forty fields.

Content model

One case study type, used on six pages. Edit once, updated everywhere.

05The rule

Name fields after what they mean.

// schemas/caseStudy.ts
defineType({
  name: 'caseStudy',
  fields: [
    client,
    sector,
    outcome,
    services,
    quote,
  ],
})
06Before any design

Four questions for the editors.

  1. 01What do you publish?
  2. 02What repeats?
  3. 03What links to what?
  4. 04Who edits which part?
07The order

Design the content. Then design the pages.

08Save this

Handover-proof in four rules.

  1. 01Model types before pages
  2. 02Name fields after meaning
  3. 03Reference content, never copy it
  4. 04Put editors in the Studio early
